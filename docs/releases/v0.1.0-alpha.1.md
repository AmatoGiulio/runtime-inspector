# Runtime Inspector v0.1.0-alpha.1

First public alpha. Runtime Inspector lets you tune a running React Native app that uses Reanimated — from a web panel or from an AI agent over MCP — and write the chosen value back into the source file it came from.

This is a developer preview: APIs and the protocol may change, and it is meant for local development on a trusted network.

## Install

From your Expo / React Native app root:

```bash
npm install @runtime-inspector/react-native@alpha
npm install --save-dev @runtime-inspector/babel-plugin@alpha @runtime-inspector/cli@alpha
npx runtime-inspector init     # Babel plugin + Metro wrapper; --dry-run to preview
npx runtime-inspector dev      # broker + web panel + Apply to code
```

Start the app with `npx expo start` and open the panel URL that `runtime-inspector dev` prints. If `init` creates `babel.config.js` in an Expo app, it asks you to run `npx expo install babel-preset-expo` too.

Install `@runtime-inspector/cli` before running `npx runtime-inspector`: an unrelated npm package is also named `runtime-inspector`.

For an AI agent, install `@runtime-inspector/client-mcp` and register `runtime-inspector-mcp` as an MCP server; it finds the running broker through `~/.runtime-inspector/session.json`.

## What is in this alpha

- `useRuntimeValue`, `useAction`, `useInspector` and `// @inspect` controls: sliders, toggles, colors, springs, Bézier curves and actions.
- Live tuning from the web panel and from MCP (`get_schema`, `set_control_value`, `batch_set`, `trigger`, `list_scenes`, `open_scene`). Invalid values are rejected with a reason, never clamped.
- **Apply to code** for source-anchored values, guarded against manual edits since the app was built.
- Stale-schema protection while the app reloads, and automatic reconnection when the app or the CLI restarts.
- The Babel plugin and the SDK do nothing in production builds.

## Packages

| Package | Role |
| --- | --- |
| `@runtime-inspector/react-native` | Runtime SDK and Metro helper |
| `@runtime-inspector/babel-plugin` | Dev-only `// @inspect` transform and source anchors |
| `@runtime-inspector/cli` | `init` and `dev`: broker, bundled web panel, Apply to code |
| `@runtime-inspector/client-mcp` | MCP server for AI agents |
| `@runtime-inspector/protocol` | Runtime Inspector Protocol types and validation |
| `@runtime-inspector/transport-ws` | Local WebSocket broker |
| `@runtime-inspector/panel-core` | Framework-agnostic panel session logic |

## Tested

Packed packages installed into a fresh `create-expo-app` project (Expo SDK 58, React Native 0.88, React 19.3, Reanimated 4.7) and run in Expo Go on the iOS Simulator with Node 22: install, `init`, dev and production bundles, live tuning from the panel and MCP, Apply to code, app reload and CLI restart.

## Known limits

- Not yet tested on Android, physical devices, bare React Native (non-Expo) apps, pnpm/yarn consumers, or Reanimated 3 with a recent Expo SDK.
- The session token in the panel URL is the only access control: whoever has it can change live values and edit source files through Apply to code. Keep the broker on a trusted network.
- The React Native DevTools panel and the macOS desktop Workbench shown in the demo run from the repository and are not published to npm yet.
- Motion discovery covers a subset of Reanimated patterns.
